# Предзаказы: сервис и админка

`orders.py` — маленький сервис на чистом Python 3.9+ (без зависимостей). Он принимает форму предзаказа
со страницы `/shop/`, хранит заказы в SQLite и отдаёт их странице `/admin/` после входа по паролю.
Сам сайт остаётся статикой; Caddy передаёт сервису только адреса `/api/*`.

Пока сервис не запущен, форма на сайте показывает «не получилось отправить» и ссылку на Telegram,
а `/admin/` — «сервер заказов недоступен».

## Установка на сервере

1. Пароль админки. Команда спросит пароль (от 10 символов) и напечатает строку с хешем — сам пароль нигде не хранится:

   ```sh
   python3 server/orders.py hash
   ```

2. Настройки — файл `/etc/pilotarbuza/orders.env` (права `600`, владелец — пользователь сервиса), по образцу `example.env`.
   Базу держите вне папки сайта, иначе её можно будет скачать по ссылке.

3. Служба systemd — `/etc/systemd/system/pilotarbuza-orders.service` (путь к репозиторию и пользователя подставьте свои):

   ```ini
   [Unit]
   Description=pilotarbuza.com preorders
   After=network.target

   [Service]
   User=www-data
   ExecStart=/usr/bin/python3 /srv/pilotarbuza.com/server/orders.py --env-file /etc/pilotarbuza/orders.env
   Restart=on-failure

   [Install]
   WantedBy=multi-user.target
   ```

   ```sh
   sudo mkdir -p /var/lib/pilotarbuza && sudo chown www-data /var/lib/pilotarbuza
   sudo systemctl daemon-reload && sudo systemctl enable --now pilotarbuza-orders
   ```

4. Caddy — в блок `pilotarbuza.com` добавьте перед `file_server`:

   ```caddy
   @private path /server/* /.git/*
   respond @private 404

   handle /api/* {
       reverse_proxy 127.0.0.1:8787
   }
   ```

   ```sh
   sudo systemctl reload caddy
   curl https://pilotarbuza.com/api/health     # {"ok": true}
   ```

## План и CRM

`crm.py` подключается к тому же сервису и хранит план работ, контакты, историю общения и календарь
в той же базе (`ORDERS_DB`, таблица `records`). При первом запуске с пустой таблицей в неё загружается
`crm_seed.json` — двухлетний план ANY1. Страница — `/admin/plan/`, вход тем же паролем.
Резервная копия — кнопка «Скачать резервную копию» в меню страницы (`/api/admin/crm/export.json`).

После обновления кода службу нужно перезапустить, иначе страница скажет, что план не загрузился:

```sh
sudo systemctl restart pilotarbuza-orders
```

## Приложение на телефоне и уведомления

`/admin/plan/` ставится на экран «Домой» как приложение (manifest и service worker — в `admin/plan/`).
На iPhone уведомления работают только так, с iOS 16.4. Включаются в разделе «Уведомления».

`push.py` и `webpush.py` отправляют Web Push без внешних библиотек (если установлен пакет `cryptography`,
он используется автоматически). Ключи VAPID создаются при первом запуске и лежат в базе. Утренняя сводка
и напоминание накануне уходят по турецкому времени, время меняется в том же разделе.

## Университет

Раздел «Университет» в приложении — расписание пар (перенесено из бота Энн, `uni_schedule.py`). Пары хранятся
в той же таблице `records` (вид `lessons`) и правятся прямо в приложении; при первом запуске подгружается
расписание осеннего семестра 2026–2027 из `crm_seed.json`. Напоминания — утром о парах на сегодня, перед первой
парой и вечером о парах на завтра — уходят через те же push-уведомления; в праздники из календаря не приходят,
на каникулы их можно поставить на паузу.

## Личное приложение

`me.py` хранит данные `/me/` в той же базе: заметки, папки, документы, операции, подписки, долги, правила стран
(таблица `me_records`), дни по странам (`me_days`), отметки геопозиции (`me_points`), бриф (`me_briefs`),
файлы — фото документов и картинки из заметок (`me_files`, до 10 МБ каждый). Страна по координатам
определяется на сервере по `server/geo/countries.json` (Natural Earth 1:50m); пересобрать — `server/build_geo.py`.

Для «Быстрых команд» iPhone и задачи с брифом есть ключи вместо пароля — выпускаются в приложении
(«Страны» → «Автоотслеживание», «Ещё» → «Бриф»), в базе хранится только хеш:

```sh
curl -X POST https://pilotarbuza.com/api/me/ping  -H 'Authorization: Bearer me_…' -H 'Content-Type: application/json' -d '{"lat":37.87,"lon":32.48,"date":"2026-10-26"}'
curl -X POST https://pilotarbuza.com/api/me/brief -H 'Authorization: Bearer me_…' --data-binary @brief.txt
```

Города («Страны» → «Города» и точки на карте) сервис находит сам: каждая отметка и фото с геопозицией сводится
к ближайшему городу из `server/geo/cities.json` (Natural Earth populated places, ~7300 городов с русскими названиями);
дальше 40 км — «рядом с городом», точки в море и в полёте пропускаются. Город можно добавить и вручную (`/api/me/cities/search`).
Глобус на главной берёт эти города с открытого `/api/places`: только центр города, название и год последнего визита
(без дат и точных отметок, кэш 10 минут); цвет пина — год.

Курсы валют сервис берёт с open.er-api.com раз в 12 часов. Напоминания (срок документа, списание подписки,
долг, лимит по стране, молчащее автоотслеживание) уходят через те же push-уведомления.

## Как это защищено

- Пароль проверяется на сервере (PBKDF2-SHA256), в коде страницы его нет. После 5 неверных попыток вход с этого адреса закрыт на 15 минут.
- Сессия — cookie `HttpOnly; Secure; SameSite=Strict` на 12 часов или на 30 дней с галочкой «Запомнить»; в базе хранится только хеш токена, перезапуск службы не разлогинивает.
- Форма: проверка всех полей на сервере, не больше 5 заявок за 10 минут с одного адреса, поле-ловушка от ботов.
- Сервис слушает только `127.0.0.1`.

## Уведомления и резервная копия

- Если в настройках заданы `TG_BOT_TOKEN` и `TG_CHAT_ID`, о каждом новом предзаказе придёт сообщение в Telegram.
- Заказы лежат в одном файле `ORDERS_DB`; копия — `sqlite3 orders.db ".backup orders-copy.db"`. В админке есть выгрузка в CSV.

## Локально

```sh
python3 server/orders.py hash                       # вставьте строку в dev.env
python3 server/orders.py --env-file dev.env --static .
# сайт и API на http://localhost:8787, админка — /admin/
```

Списки принтов, расцветок и размеров продублированы в `orders.py` и `assets/shop.js` — меняйте в обоих местах.
